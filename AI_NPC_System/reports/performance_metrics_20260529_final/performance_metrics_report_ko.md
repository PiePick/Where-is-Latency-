## 논문 삽입용 성능지표 서술 초안

본 연구는 시스템 수준의 지연시간을 모듈 단위로 분해하기 위해 런타임 로그 기반 계측을 수행하였다. SlowTrack은 최종적으로 합성되어야 하는 본문 응답의 길이를 기준으로, FastTrack은 사용자의 입력 또는 채팅 batch 입력 길이를 기준으로 구간화하였다. 분석에는 시스템 수정과 서버 재시작이 완료된 이후의 안정 구간 로그만 사용하였으며, 결측 구간에는 추정값을 삽입하지 않았다.

SlowTrack의 경우, 관측된 본문 응답은 주로 200-500자 구간에 분포하였다. 이 구간에서 SlowTrack LLM 응답 생성 평균은 1474.9 ms, TTS 음성 합성 평균은 825.4 ms였으며, 두 모듈을 합산한 평균은 2300.3 ms로 나타났다. 이는 긴 본문 응답에서 사용자가 체감하는 공백이 LLM 생성과 음성 합성의 합성 지연으로 구성됨을 보여준다.

FastTrack의 경우, 사용자 입력 길이가 증가하더라도 분석 및 검색 모듈은 수십 ms 수준에서 동작하였다. 100-200자 입력 구간의 FastTrack 전체 평균은 37.5 ms였고, 500-1000자 입력 구간에서도 FastTrack 전체 평균은 17.3 ms로 관측되었다. 이는 FastTrack이 SlowTrack 본문 생성이 시작되기 전에 짧은 반응을 제공하여 초기 무응답 구간을 줄이는 보조 경로로 기능할 수 있음을 시사한다.

다만 본 로그에서는 SlowTrack 10-100자 및 500-1000자 출력 구간의 관측치가 없었다. 따라서 해당 구간의 성능을 본문 표에 완전히 채우려면 동일한 계측 방식으로 짧은 답변 및 장문 답변을 강제하는 controlled benchmark를 추가 수집하는 것이 타당하다.
